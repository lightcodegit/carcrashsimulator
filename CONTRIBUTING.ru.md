# Как помочь

> 🌐 Эта страница на других языках: [English](CONTRIBUTING.md) · **Русский**

Проект — Godot 4.7.2 (standard, **не** .NET), GL Compatibility, GDScript. Продукт
и игровые числа описаны в `README.md`, он источник правды; этот файл — про то, как
организована работа с кодом. Правила здесь обеспечиваются CI и тестами, а не на
веру.

## Политика языка

**Язык репозитория — английский.** Все новые issues, pull request, сообщения
коммитов, комментарии в коде и строки интерфейса пишутся по-английски. Существующее
русское содержимое (старые коммиты, исторические документы в `docs/superpowers/`,
комментарии в файлах, которых вы иначе не касаетесь) остаётся как есть — историю
не переписывают ради самой истории.

## Окружение

1. Godot **4.7.2 stable** (standard-сборка). В PATH как `godot`, либо
   `export GODOT=<путь>`, либо `--godot <путь>` у каждой команды.
2. Node.js **>= 22**. npm-зависимостей нет: `tools/project.mjs` запускается без
   `npm install` и никогда не создаёт `node_modules`.
3. Для экспорта — шаблоны **4.7.2.stable** (Editor → Manage Export Templates).

```sh
node tools/project.mjs --help
node tools/project.mjs import              # обязателен после добавления или переименования .gd/.tscn
node tools/project.mjs test --timeout 400  # весь набор
node tools/project.mjs test --test h_audio --test d_params
node tools/project.mjs build windows       # или linux
node tools/project.mjs run                 # открывает окно
```

`import` обязателен, когда появляются новые классы и сцены: без него тесты не видят
файл, и провал выглядит как «такой функции не существует».

## Как устроены тесты

Харнесы лежат в `tests/` и сгруппированы по префиксу имени: `d_` — чистые данные на
`--script` (там нет autoload, трогать `TimeScale` или `ReplayRecorder` нельзя), `h_`
— проверки на уровне узлов по сценам, `p_` — ручная диагностика: замеры и скриншоты.
Прогон печатает `ALL PASS` или `FAILS <n>` и выходит в 0 или 1; `PARTIAL` — честное
признание, что часть проверки не выполнилась, `NOTE` — информация.

База: **68 проверок → 56 pass / 8 partial / 4 skipped / 0 failed**. Регресс — это
любой новый `failed` или меньшее число найденных проверок.

Главное правило: **тест обязан уметь падать.** Зелёный вывод из таймаута,
самоподсчитывающего цикла, невызванного `await` или обхода «нечего проверять» —
дефект теста, а не успех. Подтверждаемость доказывается мутацией: вернуть старое
поведение → получить `FAIL` → откатить. Откатывать правкой текста, а не копией файла
более раннего этапа работы.

Второе правило: `PARTIAL` печатается, когда выполнено условие, а не как страховка.
Строка вида «в headless звук не проверить» врёт при запуске в живом окне: там есть
и GPU, и WASAPI, а врать в отчёте нельзя. Харнесы с джойстиком (`h_vibration`,
`h_padflow`, `h_handbrake_devices`) в headless всегда partial —
`Input.get_connected_joypads()` пуст даже с подключённым геймпадом, поэтому по
headless-прогону железо не оценить.

### Ловушки headless, проверенные на себе

- вьюпорт `0×0` или квадратный — берите фактический размер, а не 1600×900 из
  `project.godot`;
- синтетические клики мышью не маршрутизируются в GUI — дёргайте кнопки сигналом
  `pressed`;
- `Performance` по времени физики отдаёт 0;
- `AudioServer.get_driver_name() == "Dummy"`, и аудиогенератор в этом случае вообще
  не создаётся;
- тесты пишут в **настоящий** `user://`: раннер изолирует его через `APPDATA`, а
  ручной запуск `Godot.exe` без `APPDATA=<пустая папка>` правит сохранённый профиль
  игрока.

## Живая верификация

```sh
APPDATA=<пустая папка> "$GODOT" --path . res://tests/p_live_probe.tscn --fixed-fps 60
```

Две-три минуты, открывает окно. Покрывает то, чего не может headless: аудиовывод,
GPU-кадр, дым и следы, окраску витрины по пикселю, снимок фотомода, три пересборки
дерева заезда. Изменения картинки или звука без такого прогона засчитанными
проверенными не считаются — напишите в PR, что именно вы видели глазами и слышали
ушами.

## Границы кода

- `scripts/maps/map_db.gd` — только фасад (`ids`/`build`/`recycle`/`debug_counts`);
  геометрия живёт в `map_kit`, `map_props`, `map_circuit`, `map_<карта>`, числа и
  палитра — в `map_defs`.
- Частицы — только `CPUParticles3D` (headless обязан считать то же, что окно),
  эммитеры дыма навешиваются на `EffectsDirector`, а не на `VehicleWheel3D`: колесо
  освобождается вместе с машиной, и активный эммитер на этом освобождении валил
  процесс.
- Аудио: один вывод на процесс, не заводить второй плеер на сцену и не освобождать
  хост в чужом `_exit_tree`.
- Реплей проигрывает записанное, а не пересимулирует: мир на паузе, поза и скорость
  берутся из кольца, вмятины пересобираются из событий в локальных координатах меша.
- Гараж: `brake_decel` обрезан физикой (`CarRig.BRAKE_MAX_G`), из `LIMITS`
  масштабируется только `accel_max`; окраска трогает ровно ячейку кузова атласа;
  `user://garage_v1.json` версионирован и пишется атомарно.
- Бинд — это клавиша вместе с модификаторами; клавиши вне `InputMap` допустимы
  только служебные и только уступчивые (`PhotoMode` спрашивает
  `InputRouter.find_owner`).
- UI: размеры через `UiTheme.fx()`/`px()`/`step()`, активные состояния через
  `UiTheme.nav_mark_active`. Не вносить пиксельные константы в код UI — ступенчатый
  рост интерфейса их ломает.

## Стиль

Сообщения коммитов следуют conventional-префиксам (`fix(ui): …`, `test: …`,
`docs: …`), а тело объясняет **почему**, а не что.

Смешение алфавитов — реальный класс дефектов в этом репозитории: случайно
забредший CJK-иероглиф или латинское слово, вклеенное в кириллическую фразу без
пробела (и наоборот — этот файл раньше был написан по-русски, и остатки склеек ещё
прячутся в старых комментариях). Перед коммитом:

```sh
grep -rnIP "[\x{4E00}-\x{9FFF}\x{3040}-\x{30FF}]" --include="*.gd" --include="*.tscn" --include="*.md" --include="*.mjs" --include="*.yml" scripts tests tools docs README.md CHANGELOG.md CONTRIBUTING.md SECURITY.md .github
```

Флаг `-I` обязателен: без него скан тонет в бинарных кэшах из `tests/tmpappdata/` и
скриншотах в `tests/out/` и даёт сотни ложных срабатываний.

## Чего не должно быть в диффе

`artifacts/`, `tests/out/`, `tests/tmpappdata/`, `*.tpz`, корневой
`export_presets.cfg` (он локальный и игнорируется; переносимые пресеты живут в
`tools/export_presets.cfg`), личные пути вида `C:/Users/…` в коде, документации и
workflow. Логика изменения не должна оставлять в репозитории одноразовые скрипты.

## Работа над issue

- **Сначала заявите его**: самоассайните issue (или прокомментируйте «беру»), прежде
  чем писать код — вдруг над ним уже работает кто-то ещё.
- **Правьте в ветке, а не в main**: именно ветку проверяет CI; в main попадают только
  через pull request.
- **Открывайте pull request со ссылкой на issue** (`fixes #N` в теле — он закроет
  issue при слиянии PR), и продублируйте ссылку на PR комментарием в issue, чтобы
  автор репорта его увидел.
- PR прогоняет полный набор на обеих платформах. Сливайте сами, когда все проверки
  зелёные — никаких обещаний будущих релизов не требуется.

## Что сначала обсудить

Изменение публичных контрактов (форматы `user://`, имена действий `InputMap`, схема
экспорта), границ движка (переезд на Forward+, другой рендерер) и границы v1 (AI-трафик,
сеть, отлетающие детали, фотореализм) — в issue, до кода. Это не бюрократия: у каждой
из этих точек уже есть тесты и документация, которые переписываются вместе с ней.

## Если вы — агент

Правила ниже взяты из практики публичных репозиториев с AI-контрибьюторами
(например, `horizon-rust/horizon`) и адаптированы под наш размер.

- **Помечайте, что пишет агент.** Тело PR начинается строкой вида
  `> 🤖 Opened by <login>'s AI agent (<tool, model>), not by <login> personally.`
  (`<login>` — аккаунт, открывший PR, `gh api user --jq .login`); в issues —
  «Filed by …», в ревью — «Review by …», каждый комментарий начинается с
  `🤖 Agent:`. Пишите только от имени того, на кого вы работаете.
- **Проверяйте, что уже делается.** Перед стартом:
  `gh pr list --state open --search <область>` и открытые issues; не дублируйте чужую
  работу. Взятая задача — назначенная на кого-то или помеченная в процессе.
- **Маленькие PR.** Ориентир — до ~500 строк диффа: один дефект или одна фича. Большие
  изменения сначала обсуждаются в issue, а не привозятся готовым поездом.
- **Не трогайте релиз.** Метки и теги релизов — решение владельца; агент не пушит теги
  `v*` и не меняет видимость репозитория.
- **Изоляция обязательна.** Каждый запуск игры или харнеса использует свежую пустую
  `APPDATA` (Windows) или `XDG_DATA_HOME`/`XDG_CONFIG_HOME` (Linux): тесты пишут в
  настоящий `user://`, и без изоляции вы правите профиль живого игрока.
- **Карта репозитория** — в `README.md`; этот файл описывает процесс вклада.
